# سامانه نمایش آگهی‌های مجتمع گاز پارس جنوبی – بوشهر

این نسخه برای مخزن `hra20776-dev/setad-tender-alert` آماده شده است. کد مرورگر مستقیماً به API ستاد وصل نمی‌شود؛ GitHub Actions اطلاعات را از سمت سرور می‌خواند و فایل `data.json` را فقط وقتی داده‌ها تغییر کرده باشند منتشر می‌کند. صفحه مشتری در هر بار بازشدن، آخرین `data.json` منتشرشده را با درخواست بدون کش می‌خواند.

## فایل‌ها

- `index.html` — صفحه ساده مشتری، جستجو در آگهی‌ها و بارگذاری دوباره داده منتشرشده.
- `scripts/fetch_setad.py` — دریافت همه صفحات با تکیه بر `totalPages` واقعی API، فیلتر ۱۰ سازمان و شهرهای استان بوشهر، حذف تکراری‌ها و کنترل تغییر داده هنگام صفحه‌بندی.
- `.github/workflows/update-setad.yml` — اجرای خودکار تقریباً هر ۵ دقیقه و انتشار تغییرات.
- `data.json` — داده‌ای که صفحه مشتری می‌خواند؛ اجرای اول آن را پر می‌کند.
- `state/seen_numbers.json` — جلوگیری از ارسال دوباره اعلان تلگرام.

## نصب در مخزن موجود

۱. فایل ZIP را استخراج کنید.
۲. محتوای پوشه را در ریشه مخزن `setad-tender-alert` بارگذاری کنید؛ فایل `index.html` قبلی جایگزین شود و پوشه‌ها/فایل‌های جدید هم اضافه شوند.
۳. در GitHub وارد مخزن شوید و تب **Actions** را باز کنید.
۴. گردش‌کار **Update South Pars Setad listings** را انتخاب کنید و یک بار **Run workflow** بزنید.
۵. پس از پایان موفق اجرا، فایل `data.json` باید با تعداد و فهرست آگهی‌های دریافت‌شده پر شود.
۶. در **Settings → Pages** مطمئن شوید سایت از شاخه `main` و پوشه `/ (root)` منتشر می‌شود.
۷. آدرس GitHub Pages همان لینک مشتری است؛ روی گوشی با گزینه Add to Home Screen میانبر بسازید.

## تلگرام (اختیاری، فقط تلگرام)

در مخزن به مسیر **Settings → Secrets and variables → Actions** بروید و دو Secret با نام‌های `BOT_TOKEN` و `CHAT_ID` بسازید. اگر تنظیم نشوند، صفحه و دریافت آگهی‌ها همچنان کار می‌کنند اما پیام تلگرام ارسال نمی‌شود. اجرای اول فقط فهرست فعلی را به‌عنوان مبنا ذخیره می‌کند و آگهی‌های قدیمی را یک‌باره به تلگرام نمی‌فرستد؛ اجراهای بعدی فقط شماره‌های جدید را اعلان می‌کنند.

## رفتار به‌روزرسانی و محدودیت مهم

- گردش‌کار طبق زمان‌بندی GitHub حدود هر ۵ دقیقه اجرا می‌شود؛ GitHub ممکن است شروع اجرای زمان‌بندی‌شده را به‌ویژه هنگام شلوغی با تأخیر انجام دهد.
- با بازشدن صفحه یا زدن «بارگذاری مجدد»، مرورگر آخرین فایل منتشرشده را دوباره می‌خواند؛ این دکمه اجرای فوری API یا workflow را آغاز نمی‌کند.
- GitHub Pages یک سایت ایستا است؛ بنابراین بدون یک سرور/تابع واسط جداگانه، دریافت زنده در لحظه کلیک ممکن نیست. این نسخه از GitHub Actions برای همگام‌سازی دوره‌ای رایگان استفاده می‌کند.
- تعداد آگهی‌ها ثابت نیست. اسکریپت تعداد صفحات را از `totalPages` می‌خواند و تا پایان همه صفحات جلو می‌رود؛ سقف ثابت ۱۶۱ یا ۲۰۰ رکورد ندارد.
- اگر دریافت هر صفحه یا کنترل یکپارچگی ناموفق باشد، فایل قبلی `data.json` دست‌نخورده می‌ماند تا فهرست ناقص منتشر نشود.
- زمان‌بندی هر ۵ دقیقه تقریبی است و به زمان‌بندی GitHub Actions وابسته است؛ این سامانه تضمین لحظه‌ای/بلادرنگ نمی‌دهد.
